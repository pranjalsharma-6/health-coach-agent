# Deploying Kaya

The goal here is specific: **a recruiter clicks your link and sees the app in
under three seconds, cold.** That is the bar the Streamlit deployment failed,
and everything below exists to clear it.

---

## Why not Streamlit Cloud

Not a criticism of Streamlit — it's the wrong shape for this job:

| | Streamlit Cloud | This setup |
|---|---|---|
| Cold start | 30–60s, sometimes times out | Frontend instant (CDN); API warm via ping |
| Frontend hosting | One Python container | Static CDN edge, globally replicated |
| Scaling | Whole app is one process | Frontend and API scale independently |
| Failure blast radius | API hiccup blanks the page | Frontend renders, shows a clear error |

Splitting the frontend off is what removes the cold start from the visitor's
path entirely: Vercel serves prebuilt HTML from an edge node with no container
to wake. Only the API can be cold, and the keepalive workflow handles that.

---

## Architecture

```
  Browser
     │
     ├──────────────► Vercel (Next.js)        ← static, CDN edge, no cold start
     │                    │
     │                    │  NEXT_PUBLIC_API_URL
     │                    ▼
     └──────────────► Render (FastAPI)        ← kept warm by a scheduled ping
                          │
                          ▼
                    MongoDB Atlas             ← pool opened at startup
```

## 1. MongoDB Atlas

1. Create a free **M0** cluster at [cloud.mongodb.com](https://cloud.mongodb.com).
2. **Database Access** → add a user with *Read and write to any database*. Use a
   generated password and copy it.
3. **Network Access** → add `0.0.0.0/0`.
   Render's free tier has no static outbound IP, so an allowlist can't be
   narrowed. The database is still protected by credentials and TLS — but this
   is a real trade-off, and on a paid tier you would pin the egress IP instead.
4. Copy the connection string. It looks like:
   ```
   mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```
   URL-encode the password if it contains `@`, `:`, `/` or `#`.

## 2. Backend on Render

The repo has a `render.yaml` blueprint, so this is mostly clicking through.

1. [dashboard.render.com](https://dashboard.render.com) → **New** → **Blueprint**.
2. Connect the repo and select the branch. Render reads `render.yaml`.
3. Fill in the secrets it prompts for:

   | Variable | Value |
   |---|---|
   | `MONGODB_URI` | your Atlas connection string |
   | `GROQ_API_KEY` | from [console.groq.com](https://console.groq.com) |
   | `CORS_ORIGINS` | your Vercel URL (fill in after step 3, then redeploy) |

   `JWT_SECRET` is generated by Render — don't set it yourself.
4. Deploy, then check `https://your-api.onrender.com/health`. You want:
   ```json
   { "status": "healthy", "database": { "status": "healthy" }, "llm_configured": true }
   ```

   `"status": "degraded"` means the database didn't connect — check the Render
   logs for the reason, usually a wrong password or a missed Network Access rule.

## 3. Frontend on Vercel

1. [vercel.com/new](https://vercel.com/new) → import the repo.
2. **Root Directory: `frontend`.** This is the step people miss; without it the
   build fails because there's no `package.json` at the repo root.
3. Framework preset: Next.js (auto-detected).
4. Environment variable:

   | Variable | Value |
   |---|---|
   | `NEXT_PUBLIC_API_URL` | `https://your-api.onrender.com/api/v1` |

   Note the `/api/v1` suffix — the client appends paths directly to it.
5. Deploy.

### Then close the CORS loop

Go back to Render and set `CORS_ORIGINS` to your Vercel URL, e.g.
`https://kaya.vercel.app`, and redeploy.

Skipping this is the single most common failure: the app loads, looks perfect,
and every request fails. In the browser console it reads:

```
Access to fetch at 'https://your-api.onrender.com/...' from origin
'https://kaya.vercel.app' has been blocked by CORS policy
```

If you add a custom domain later, add it to `CORS_ORIGINS` too — Vercel preview
deployments get their own URLs and will be blocked unless included.

## 4. Keep the API warm

`.github/workflows/keepalive.yml` pings `/health` every 10 minutes.

Set the repository variable so it knows where to ping:
**Settings → Secrets and variables → Actions → Variables → New** →
`KAYA_API_URL` = `https://your-api.onrender.com`

Until it's set the workflow skips itself rather than failing.

**Be honest with yourself about this one.** It's a workaround for free-tier
spin-down, not architecture. It burns Actions minutes and it isn't a guarantee —
GitHub's scheduler runs late under load. If this project ever matters to you
beyond a portfolio piece, the real fix is Render's paid tier (~$7/month) with no
spin-down at all.

---

## 5. Verify like a stranger

Not from the tab you've had open for an hour:

1. **Open in a private window.** No cached bundle, no stored token.
2. **Register a fresh account** and complete onboarding.
3. **Generate a plan.** Watch the agent stream its steps.
4. **Mark a meal skipped**, then run the agent again. The plan should change and
   say why.
5. **Load it on your phone**, on mobile data rather than wifi.

If step 1 takes more than a few seconds, the API was cold — check that the
keepalive workflow is actually running under the Actions tab.

## Troubleshooting

**Every request fails with a CORS error.**
`CORS_ORIGINS` on Render doesn't include your exact Vercel origin. It must match
scheme and host with no trailing slash: `https://kaya.vercel.app`.

**`/health` reports `"database": {"status": "unhealthy"}`.**
Wrong `MONGODB_URI`, an un-encoded password, or Atlas Network Access missing
`0.0.0.0/0`.

**Agent runs fail with 503.**
`GROQ_API_KEY` isn't set, or you're being rate-limited. `/health` shows
`llm_configured` so you can tell those apart.

**The logs say `LLM MISCONFIGURED` at startup, or a run fails naming a model.**
`LLM_MODEL` is set to a name belonging to a different provider than the key in
use — a Gemini name with a Groq key, say. The message names both fixes. The
simplest is to remove `LLM_MODEL` entirely and let the provider default apply.

**The agent retries three times and gives up.**
The model's plan is failing validation. The streamed timeline names the exact
rule — usually the protein floor. Either loosen `PROTEIN_TOLERANCE` in
`backend/app/agent/validators.py` or strengthen the per-meal protein guidance in
`backend/app/agent/prompts.py`. Don't remove the check.

**Vercel build fails: "no package.json found".**
Root Directory isn't set to `frontend`.

**First load is slow but later ones are fast.**
Cold start. Expected on the free tier; that's what the keepalive is for.
